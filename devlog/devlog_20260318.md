### 2. 인출률 분석 (핵심 발견)

- 15% 인출률의 실효인출률: **평균 11.8%, 최고 13.1%** (15%에 근접 불가)
- Band 넓히면: 실효인출률 상승하지만 **총가치는 오히려 하락** (+-5%가 최적)
- **Guardrail의 본질**: Fixed보다 인출을 억제하여 복리 효과 보존 → AUM 장기 유지
- **실효인출률 vs Fixed 비교**: 저인출률(3~8%)에서 Guardrail 타이밍 알파 존재, 고인출률(12%+)에서는 알파 소멸

### 3. 신규 상품 펀드 데이터 파이프라인

**대상**: Golden Growth, MS GROWTH, MS STABLE (product_mp_20260317 기반)

**구축 과정**:
1. `bm_list` (17개 자산 일별 가격지수) + `MP_Position_20260317` (일별 MP 비중)
2. `build_product_paths.py`: KRW 환산 수익률 → Rolling 55개 + Bootstrap 181개 경로
3. `grid_search_product.py`: 기존 pkl에 합산 → 9개 포트폴리오 27,000건

**주요 이슈 및 해결**:

#### USD T-1 래그
- 기준가 산출 시 USD 자산은 T-1일 종가 반영 (`usd_ret.shift(1)`)
- 이전 코드: 동일 날짜 수익률 × 환율변동 → **수익률 과대평가** (연 2%p 차이)
- 수정 후: T-1 래그 반영 → Golden Growth 연수익률 14.3% → 12.1%

#### MP 자산명 불일치
- MP: "한국 10년국고채**권**" / ASSET_MAP: "한국 10년국고채" → 매칭 안 됨
- MS STABLE에서 국고채 69.34% 누락 → 주식/대체 비중이 3배 과대 → 수익률 왜곡
- 해결: `MP_NAME_ALIAS` 딕셔너리로 표준화, 중복 키 제거

#### 엑셀 월간 T-1 래그 오류
- 일별 T-1 래그를 월별 BM 지수에 직접 적용 → **한 달 래그** 발생
- 해결: 엑셀을 **일별 데이터**(2,609행)로 전환, Python과 동일 로직

## 대화 주요 논점

### Guardrail 상품의 본질
> "사실 이 상품의 본질은 fixed 보다 인출을 못시키게 해서 최대한 운용수익을 많이 들고 갈수있게끔 해주는거잖아."

→ 판매사에는 "AUM 유지 = 보수 장기화"로 직접 언급, 고객에는 "총가치 극대화 + 파산 방지"로 프레이밍

### 인출률 설정
- 15% 인출 시 실효 12.4% → "15% 상품"이라고 마케팅하면 거짓말
- **12%가 정직한 구간** (실효 11.4%, 명목 괴리 적음)

### USD T-1 래그 중요성
- 기준가 산출: T일 KRW = USD(T-1) × 환율(T)
- 이걸 안 하면 연 수익률 2%p 과대평가
- 월별 엑셀에서 T-1을 구현하면 한 달 래그 → **반드시 일별로 래그 후 월간 복리**

### 일별 복리 vs 월간 SUMPRODUCT
- 같은 비중, 같은 BM 데이터인데 0.07%p 차이 발생
- 원인: 일별 복리 = 매일 고정비중 리밸런싱, 월간 SUMPRODUCT = 월초 비중으로 drift 허용
- 해결: 엑셀을 일별 데이터로 전환하여 Python과 완전 동일 로직
